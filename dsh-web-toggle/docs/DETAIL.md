# 联网开关

输入框工具栏上的一个小开关，只干一件事：控制**当前会话**的模型能不能看到 `web_search` / `web_fetch`。

## 用法

- 工具栏左侧的「联网」按钮：亮着 = 开，图标被斜线划掉 = 关。
- 点一下切换。也可以在输入框里敲命令：

| 命令 | 作用 |
| --- | --- |
| `/webtoggle` | 切换本会话的联网开关 |
| `/webtoggle off` | 关（幂等：重复关不会叠加限制） |
| `/webtoggle on` | 开 |
| `/webtoggle status` | 只看当前状态，不改 |

命令结果末尾带一个机器可读标记（`[web:on]` / `[web:off]`），按钮用它同步真实状态。

## 行为

- 关闭后，本会话的 Agent 上下文被 `tools.restrict({ deny: ['web_search', 'web_fetch'] })` 加上遮罩，下一次请求的工具声明里就没有这两个工具；模型调用会得到 unknown tool。
- 恢复时调用当时存下的那个 disposer，遮罩被精确撤销。
- 状态按**会话**记录，互不影响：关掉 A 会话不会影响 B 会话。
- 工具列表变了会重建请求序列（`agent/pre-step` → `startsRequestSeries`），避免新声明被上游当成「延迟追加」。

## 边界与限制

- **轮次进行中不改**：任务正在跑时点按钮会直接拒绝并提示，等这一轮结束再切。理由是不会在轮次中途换工具集（那会让同一轮的前后请求声明不一致）。
- **只管这两个工具**：`search` / `fetch` 以外的工具不碰；关掉联网不等于关掉沙箱或权限。
- **重启重置**：DSH 重启后 Host 侧状态清零（工具恢复可见）。按钮挂载时如果浏览器记着「关」，会向 Host 探一次 `/webtoggle status` 把显示纠正过来，因此不会出现「明明开着却显示关」。
- 会话销毁会撤销遮罩并清理记录，限制不会泄漏到别的会话。

## 相关实现

- `index.js`：`/webtoggle` 命令、`tools.restrict()` 遮罩与 disposer 管理、请求序列重建、会话销毁清理。
- `client.js`：`conversation.input.left` 槽位组件、按会话铭记的显示状态、`commands.execute` 调用。
